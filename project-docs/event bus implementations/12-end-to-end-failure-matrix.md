# End-to-End Failure Matrix

This matrix is the review map for the root-Compose failure scenarios. It separates automated seam evidence that runs in the normal backend test suite from the live Compose gate that must be executed in an environment with the required broker, database, blob, Speech, and Clinical Knowledge dependencies.

The automated evidence proves the business and event-bus invariants. The Compose gate proves the same behavior across real process, container, network, and broker boundaries.

| ID | Scenario | Automated seam evidence | Live Compose gate | Expected user/system outcome |
| --- | --- | --- | --- | --- |
| E2E-01 | Happy audio path: upload -> outbox -> RabbitMQ -> worker -> Transcript Ready -> backend -> Clinical Knowledge | `Audio_upload_commits_consultation_and_outbox_without_request_thread_publish`; `Relay_marks_outbox_message_published_only_after_confirmed_publish_returns`; `HandleAsync_retrieves_audio_transcribes_and_commits_completion_unit_of_work`; `HandleAsync_prepares_backend_session_transcript_request_without_message_text_payload`; `CompleteAcceptedAsync_marks_inbox_completed_with_ingestion_and_document_identity` | Start root Compose, upload a synthetic audio file, wait for transcript and Clinical Knowledge ingestion identity. | Doctor upload is accepted; transcript becomes available; downstream knowledge ingestion is durable without exposing transcript text on RabbitMQ. |
| E2E-02 | Broker outage at upload | `Audio_upload_commits_consultation_and_outbox_without_request_thread_publish`; `Relay_schedules_backoff_when_confirmed_publish_fails`; `Relay_marks_outbox_message_published_only_after_confirmed_publish_returns` | Stop RabbitMQ, upload synthetic audio, restart RabbitMQ, verify outbox lag drains. | Upload remains accepted and recoverable; no client re-upload is required. |
| E2E-03 | Worker crash before completion commit | `ClaimAsync_reclaims_expired_in_progress_event`; `CompleteAsync_commits_inbox_transcript_consultation_status_and_result_outbox` | Kill worker while Speech work is in progress; restart worker after lease expiry. | Redelivery completes the work once; abandoned in-progress inbox state does not strand the Consultation File. |
| E2E-04 | Worker crash after commit but before ACK | `CompleteAsync_treats_completed_inbox_event_as_duplicate_noop`; `HandleAsync_skips_blob_and_speech_when_inbox_event_is_already_completed` | Kill worker immediately after completion commit before ACK; observe redelivery. | Duplicate delivery ACKs as a no-op and does not call Blob/Speech or create a second Transcript. |
| E2E-05 | Speech transient outage, five retries, DLQ, repair, controlled replay | `Handler_failure_returns_retry_outcome`; `Retry_queues_dead_letter_back_to_the_exchange_with_the_original_routing_key`; `Replay_publishes_the_original_immutable_dead_letter_envelope_after_operator_approval`; `Replay_denies_payload_editing_and_does_not_publish` | Configure Speech adapter to fail transiently through all retries, verify DLQ, repair dependency, replay with operator/reason. | Retries are bounded; DLQ is recoverable through approved replay; payload JSON is never edited. |
| E2E-06 | Permanent invalid audio | `TranscribeAsync_classifies_empty_transcript_as_permanent_failure`; `HandleAsync_commits_transcription_failed_for_permanent_speech_failure`; `FailAsync_commits_failed_transcript_consultation_inbox_and_failure_outbox` | Upload deterministic unsupported/invalid synthetic audio. | Consultation reaches terminal Transcription Failed state/event and ACKs without a DLQ loop. |
| E2E-07 | Document upload isolation | `Document_upload_commits_document_event_without_original_filename_or_identity`; `Worker_registration_binds_only_audio_uploaded_to_a_standard_rabbitmq_consumer`; `Future_document_processor_topology_binds_only_document_uploaded_events` | Upload a synthetic PDF/document while worker is running. | Document Uploaded exists; Transcription Worker does not receive document work or create a placeholder Transcript. |
| E2E-08 | Deletion race during Speech | `ClaimAsync_completes_and_skips_deleted_consultation_before_expensive_work`; `CompleteAsync_marks_inbox_completed_but_ignores_deleted_consultation`; `PrepareAsync_ignores_deleted_consultation_without_returning_transcript_text`; `HandleAsync_deletes_blob_refs_uningests_documents_and_marks_resources_completed` | Start audio processing, delete Consultation before completion, let worker/backend drain. | Deleted Consultation wins; no Transcript or knowledge content survives or is recreated by stale events. |
| E2E-09 | Transcript correction | `Transcript_correction_increments_revision_and_stages_transcript_ready_outbox`; `PrepareAsync_loads_current_transcript_context_and_keeps_inbox_in_progress_until_acceptance`; `CompleteAcceptedAsync_marks_inbox_completed_with_ingestion_and_document_identity` | Edit a completed Transcript and verify a new revision ingests with stable Clinical Knowledge identity. | Correction supersedes the prior knowledge document instead of creating unrelated duplicates. |
| E2E-10 | Backend or Clinical Knowledge outage after Transcript completion | `PrepareAsync_loads_current_transcript_context_and_keeps_inbox_in_progress_until_acceptance`; `HandleAsync_does_not_call_clinical_knowledge_when_preparation_skips_event`; `Handler_failure_returns_retry_outcome` | Stop Clinical Knowledge API after Transcript Ready, restart it, observe retry and ingestion completion. | Transcript remains complete; downstream handoff retries and later converges. |
| E2E-11 | Scale-out of relays/workers | `Validator_accepts_safe_scaling_defaults`; `Worker_registration_uses_transcription_concurrency_to_bound_rabbitmq_prefetch_and_shutdown`; `ClaimAsync_returns_duplicate_completed_without_reclaiming`; `CompleteAsync_treats_completed_inbox_event_as_duplicate_noop` | Run multiple backend API and Transcription Worker replicas with bounded prefetch/concurrency. | Backlog drains without duplicate business effects or dependency overload. |
| E2E-12 | Graceful shutdown | `Worker_registration_uses_transcription_concurrency_to_bound_rabbitmq_prefetch_and_shutdown`; `Validator_rejects_worker_concurrency_that_can_exceed_quota_or_lease_safety`; `RabbitMqConsumerOptionsValidatorTests` | Stop worker during active work and verify bounded drain or redelivery after lease expiry. | Active work either finishes within drain or safely redelivers; no partial business commit is accepted. |

## How to use this matrix

1. Run the automated backend tests first. They prove event contracts, outbox/inbox idempotency, retry/replay policy, state gates, and privacy assertions.
2. Start the root Compose stack from `docker-compose.yml` with environment values copied from `compose.env.example`.
3. Execute each live Compose gate with synthetic fixtures only.
4. Record the observed event ID, subscriber, safe Consultation ID, result state, and any DLQ/replay action. Do not copy payload bodies, blob paths, transcript text, provider responses, or exception messages into tickets.
5. Close the scenario only when the expected outcome and reconciliation checks both pass.
